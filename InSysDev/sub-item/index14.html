　　本页以"实验1 跑马灯实验"（标准例程-HAL库版本）工程为对象，参考《STM32F429 阿波罗开发指南 V1.2》第十三章《跑马灯实验》，章节顺序与手册小节保持一致；其中第 3 章"软件设计"按照程序启动的先后顺序逐层解析代码。本章先掌握 STM32F429 的 IO 口作为输出的使用方法（对应手册 13.1 节），为后续解析 LED 驱动代码打好基础。

1.1 IO 简介与八种工作模式

　　手册 13.1.1 节给出 GPIO 的八种工作模式：输入浮空、输入上拉、输入下拉、模拟、开漏输出、推挽输出、开漏式复用、推挽式复用。八种模式由 MODER/OTYPER/OSPEEDR/PUPDR 四个配置寄存器组合决定（表 13.1.3.1）：MODER 区分输入(00)/输出(01)/复用(10)/模拟(11)四大类，OTYPER 在输出类中区分推挽/开漏，PUPDR 决定是否接内部上/下拉。跑马灯实验取"输出(01) + 推挽(0) + 上拉(01)"组合，即推挽输出——P-MOS 负责拉高、N-MOS 负责拉低，两管轮流导通，驱动 LED 毫无压力（推挽模式驱动能力最大 25mA）。

1.2 GPIO 功能复用

　　手册 13.1.2 节指出：STM32F429 的每个 IO 口都可作为复用功能引脚（如 USART、SPI、I2C、定时器等外设信号），由两个 32 位复用功能选择寄存器 AFRL/AFRH 配置——AFRL 控制 IO0~IO7、AFRH 控制 IO8~IO15，每 4 位对应一个 IO 的 AF0~AF15 十六种复用功能编号。本实验把 PB0/PB1 用作普通 GPIO 输出（MODER=01 通用输出模式），不涉及复用配置，故 GPIO_InitTypeDef 的 Alternate 成员无需设置。

1.3 GPIO 相关寄存器

　　每组 GPIO 挂载在 AHB1 总线上（GPIOA~GPIOK 基址 0x40020000 起，每组 0x400 字节）。GPIOB 的 ODR 地址为 0x40020414。关键寄存器如下（手册 13.1.3 节）：

寄存器作用
MODER模式寄存器：每 2 位控制 1 个 IO——00 输入 / 01 通用输出 / 10 复用功能 / 11 模拟。GPIOB 复位值 0xFFFFFEBF，即 PB0/PB1 复位后默认为模拟模式
OTYPER输出类型寄存器：每 1 位控制 1 个 IO——0 推挽 / 1 开漏（仅输出模式有效）
OSPEEDR输出速度寄存器：每 2 位控制 1 个 IO——00 低速 / 01 中速 / 10 快速 / 11 高速
PUPDR上下拉寄存器：每 2 位控制 1 个 IO——00 无上下拉 / 01 上拉 / 10 下拉（弱上拉约 30~50KΩ）
IDR输入数据寄存器（只读）：读取引脚实际电平
ODR输出数据寄存器（可读可写）：写 1 输出高、写 0 输出低；改电平需整体重写、有被中断打断的风险
BSRR置位/复位寄存器（只写）：低 16 位 BSy 写 1 置高、高 16 位 BRy 写 1 置低、写 0 无影响——无需先读后改，原子操作不可被中断打断
LCKR引脚配置锁定寄存器：冻结引脚配置直至复位
AFRL/AFRH复用功能选择寄存器：每 4 位选择 AF0~AF15（见 1.2 节）

　　对比数据类寄存器：ODR 可读可写但整体重写；BSRR 只写但一次 32 位写入只改变目标引脚、原子生效——这就是 HAL 库控制电平选用 BSRR 的原因（见 3.8.2 节），也是位带操作（见 3.7.1 节）能"一个位一个地址"的硬件基础。

1.4 HAL 库 GPIO 驱动与输出配置步骤

　　手册 13.1.4 节介绍 HAL 库 GPIO 驱动。使用 HAL 库操作 GPIO 的核心是 GPIO_InitTypeDef 初始化结构体与三个常用函数：

结构体成员取值示例含义
PinGPIO_PIN_0 | GPIO_PIN_1指定引脚号，可用"|"一次选多个（PB0、PB1）
ModeGPIO_MODE_OUTPUT_PP模式选择（还能选 OD 开漏、AF 复用、ANALOG 模拟、IT 外部中断等）
PullGPIO_PULLUP上下拉配置（NOPULL / PULLUP / PULLDOWN）
SpeedGPIO_SPEED_HIGH输出速度等级（LOW / MEDIUM / HIGH / VERY_HIGH 四档）
Alternate未设置复用功能编号（AF0~AF15），仅在 AF 模式下使用
HAL 库函数功能说明
HAL_GPIO_Init()按结构体参数初始化一个或多个 IO 口的 MODER/OTYPER/OSPEEDR/PUPDR（同一组口的 Mode/Pull/Speed 等参数一致时才可一次初始化多个）
HAL_GPIO_WritePin()控制引脚输出高/低电平（写 BSRR，见 3.8.2 节）
HAL_GPIO_TogglePin()翻转引脚输出电平（写 ODR 取反）

　　GPIO 输出配置三步骤（手册 13.3.1 节总结，跑马灯的 LED_Init 即按此展开）：

  • 1使能 GPIO 时钟　STM32 任意外设使用前必须先开时钟，通过 __HAL_RCC_GPIOx_CLK_ENABLE() 宏置位 RCC->AHB1ENR；
  • 2设置工作模式　填充 GPIO_InitTypeDef 结构体，调用 HAL_GPIO_Init() 写入四个配置寄存器——"先清旧值、再写新值"：对 Pin 选中位段清零后，按 Mode 写 MODER，输出类再写 OTYPER/OSPEEDR，按 Pull 写 PUPDR；
  • 3控制引脚电平　用 HAL_GPIO_WritePin()（或 ODR/BSRR/位带）输出高、低电平。

　　以本实验配置（PB0/PB1 推挽输出+上拉+高速）为例，HAL_GPIO_Init 落地到寄存器的写入值为：

寄存器写入值作用
MODERPB0/PB1 位段 = 01通用输出模式
OTYPERPB0/PB1 位 = 0推挽输出
OSPEEDRPB0/PB1 位段 = 10高速
PUPDRPB0/PB1 位段 = 01上拉
本章小结

GPIO 八种模式由四个配置寄存器组合决定；数据控制靠 ODR（整体写）与 BSRR（原子写）；HAL 库以 GPIO_InitTypeDef + HAL_GPIO_Init 封装寄存器配置，输出配置遵循"开时钟→设模式→控电平"三步骤。带着这些知识进入第 2、3 章。

2 硬件设计（对应手册 13.2）

2.1 实验目标与现象

　　跑马灯实验是 STM32 学习的第一个物理输出实验，目的在于验证开发环境与下载流程、掌握 GPIO 输出的完整链路。实验现象：LED0 与 LED1 每隔 500ms 交替点亮/熄灭一次，实现类似跑马灯的效果。

2.2 硬件资源与电路

　　依据手册 13.2 节《硬件设计》，本实验硬件资源如下：

资源连接引脚说明
LED0PB1低电平点亮（阳极经限流电阻接 3.3V，阴极接 IO 口）
LED1PB0低电平点亮，与 LED0 同电路

　　LED 电路在开发板上已经固定连接，无需改动任何硬件。由于 IO 输出低电平时 LED 导通点亮，输出高电平时熄灭，所以代码中"灯亮"对应引脚写 0，"灯灭"对应引脚写 1——这一点贯穿整个工程代码的注释。

3.2 启动文件解析（startup_stm32f429xx.s）

　　启动文件是一段汇编程序（MDK-ARM 工具链版本），上电后最先执行的部分由它完成。它首先定义了系统要用的栈和堆空间：

; Amount of memory (in bytes) allocated for Stack Stack_Size EQU 0x400; ; 栈空间大小：1024 字节 AREA STACK, NOINIT, READWRITE, ALIGN=3 ; 8 字节对齐的栈段 Stack_Mem SPACE Stack_Size __initial_sp ; 栈顶地址标号（栈从高地址向低生长） Heap_Size EQU 0x200; ; 堆空间大小：512 字节 AREA HEAP, NOINIT, READWRITE, ALIGN=3 __heap_base Heap_Mem SPACE Heap_Size __heap_limit ; 堆底地址标号（堆从低地址向高生长）

3.2.1 栈与堆的分配

　　栈（STACK）用于函数调用时的局部变量、寄存器现场保护等，大小 0x400（1KB）；堆（HEAP）供 malloc 等动态内存分配使用，大小 0x200（512B）。__initial_sp 标号位于栈空间末尾，即栈顶指针 MSP 复位后的初始值——它在下一步将被硬件直接加载。

3.2.2 中断向量表

　　启动文件在只读数据段 RESET 中建立了中断向量表（与 index13 页面第 2.2 节相呼应）。向量表本质是一个函数入口地址数组，其前两个字具有特殊身份：

AREA RESET, DATA, READONLY EXPORT __Vectors __Vectors DCD __initial_sp ; Top of Stack —— 向量表第 0 项：主栈指针 MSP 初始值 DCD Reset_Handler ; Reset Handler —— 第 1 项：复位中断服务程序入口 DCD NMI_Handler ; NMI Handler DCD HardFault_Handler ; Hard Fault Handler ... ;（系统异常 + 91 个外设中断入口，共 90 余项） DCD SysTick_Handler ; SysTick Handler

　　地址 0x0000 0000 处存放的不是指令，而是 MSP 的初始值（__initial_sp）；地址 0x0000 0004 处才是第一个服务程序 Reset_Handler 的入口地址。后面的条目依次是 NMI、HardFault、SysTick 等系统异常和 WWDG、USART1 等外设中断的默认服务函数（均为 [WEAK] 弱定义的死循环空函数，用户代码中同名函数会覆盖它们——例如 stm32f4xx_it.c 中的 SysTick_Handler）。

3.2.3 Reset_Handler 复位处理

　　上电或复位后，Cortex-M4 内核自动完成两件事：从 0x0000 0000 取出值装入 MSP（栈指针），从 0x0000 0004 取出值装入 PC（程序计数器）——于是 CPU 开始执行 Reset_Handler：

; Reset handler Reset_Handler PROC EXPORT Reset_Handler [WEAK] IMPORT SystemInit ; 声明外部函数：位于 system_stm32f4xx.c IMPORT __main ; 声明外部函数：C 库初始化入口 LDR R0, =SystemInit BLX R0 ; 第一步：跳转执行 SystemInit，初始化时钟/FPU/向量表 LDR R0, =__main BX R0 ; 第二步：跳入 __main，之后永不返回（由 C 库最终调到用户 main） ENDP

　　Reset_Handler 只做两件事：先调用 SystemInit（3.3 节解析），再跳转到 __main（3.3.3 小节解析）。注意这里的 __main 是 ARM C 库的入口函数，不是用户编写的 main()。启动文件末尾还提供了堆栈初始化函数 __user_initial_stackheap（把 Heap_Mem/Stack_Mem 的边界告知 C 库），供标准 C 库在 __main 中调用。

3.3 SystemInit 与 __main

3.3.1 SystemInit 初始化

　　SystemInit 位于 USER/system_stm32f4xx.c，在进入 main 之前被 Reset_Handler 调用，把芯片恢复到一个"干净的已知状态"：

void SystemInit(void) { /* FPU settings --- 使能 FPU -----------------------------------------*/ #if (__FPU_PRESENT == 1) && (__FPU_USED == 1) SCB->CPACR |= ((3UL << 10*2)|(3UL << 11*2)); /* CP10、CP11 完全访问权 */ #endif /* Reset the RCC clock configuration to the default reset state */ RCC->CR |= (uint32_t)0x00000001; ; 开启 HSI（内部 16MHz） RCC->CFGR = 0x00000000; ; 复位时钟配置寄存器 RCC->CR &= (uint32_t)0xFEF6FFFF; ; 关闭 HSE、CSS、PLL RCC->PLLCFGR = 0x24003010; ; 复位 PLL 配置寄存器（M=16, N=192...默认值） RCC->CR &= (uint32_t)0xFFFBFFFF; ; 复位 HSEBYP RCC->CIR = 0x00000000; ; 关闭所有 RCC 时钟中断 ... }

　　要点有三：① 开启 FPU（F429 带 FPU，写 CPACR 的 CP10/CP11 位开放协处理器访问权，此后编译出的浮点指令才能使用）；② 复位全部时钟配置——注意此时系统时钟是 HSI 16MHz（变量 SystemCoreClock 初始值即为 16000000），真正的 180MHz 主频要到 main 里 Stm32_Clock_Init 才配置；③ 本工程未定义 DATA_IN_ExtSRAM/ExtSDRAM，不初始化外部存储器。

3.3.2 向量表定位 VTOR

/* Configure the Vector Table location add offset address ---*/ #ifdef VECT_TAB_SRAM SCB->VTOR = SRAM_BASE | VECT_TAB_OFFSET; /* 向量表重定位到 SRAM */ #else SCB->VTOR = FLASH_BASE | VECT_TAB_OFFSET; /* 向量表定位在内部 FLASH */ #endif

　　本工程 USER/system_stm32f4xx.c 中 VECT_TAB_SRAM 未定义、VECT_TAB_OFFSET = 0x00，因此执行 SCB->VTOR = 0x08000000，把向量表明确指向内部 FLASH 首地址。此后发生中断时，NVIC 都到 0x08000000 起始的表中查入口地址（复位瞬间硬件默认也映射到 FLASH，此处再显式设置一次以保万全）。

3.3.3 __main 与 C 库初始化

　　SystemInit 返回后，Reset_Handler 执行 BX R0 跳入 __main。__main 是 ARM 编译器 C 运行时库的入口，它完成从"裸汇编环境"到"能跑 C 程序的环境"的过渡：

  • 1 Scatter-Loading 数据搬运　把已初始化的全局/静态变量（RW 数据）从 FLASH 拷贝到 RAM；把未初始化的全局/静态变量（ZI 数据）所在的 RAM 区清零。对应编译信息中的 RW-data 与 ZI-data；
  • 2 堆栈初始化　调用启动文件提供的 __user_initial_stackheap（或 MicroLib 的等效机制），建立 C 库使用的堆与栈；
  • 3 进入 main　环境就绪后，C 库最终调用用户的应用程序入口 main()，从此进入跑马灯工程的 C 世界，永不返回。

3.4 HAL_Init 解析

　　进入 main 后，第一行代码就是 HAL_Init()（HALLIB/STM32F4xx_HAL_Driver/Src/stm32f4xx_hal.c）。手册要求：main 程序中它必须是第一条被执行的指令，先于任何其他 HAL 函数调用。

3.4.1 Flash 缓存与预取

HAL_StatusTypeDef HAL_Init(void) { /* Configure Flash prefetch, Instruction cache, Data cache */ #if (INSTRUCTION_CACHE_ENABLE != 0) __HAL_FLASH_INSTRUCTION_CACHE_ENABLE(); ; 指令缓存 ICEN 置位 #endif #if (DATA_CACHE_ENABLE != 0) __HAL_FLASH_DATA_CACHE_ENABLE(); ; 数据缓存 DCEN 置位 #endif #if (PREFETCH_ENABLE != 0) __HAL_FLASH_PREFETCH_BUFFER_ENABLE(); ; 预取缓冲 PRFTEN 置位 #endif ...

　　三个开关宏在 USER/stm32f4xx_hal_conf.h 中均定义为 1，因此 HAL_Init 先打开 FLASH 的预取缓冲、指令缓存、数据缓存（写 FLASH->ACR 寄存器），提升取指效率，为后面切到 180MHz 高主频做准备。

3.4.2 NVIC 优先级分组

/* Set Interrupt Group Priority */ HAL_NVIC_SetPriorityGrouping(NVIC_PRIORITYGROUP_2);//中断优先级分组2

　　这一行把 AIRCR 的 PRIGROUP 设为分组 2：4 位优先级中，2 位抢占优先级（0~3）+ 2 位响应优先级（0~3）（与 index13 页面第 2.5 节的分组表对应）。整个工程只需在这里设置这一次，后续所有外设中断的优先级都在此框架下分配。

3.4.3 SysTick 时基与 HAL_MspInit

/* Use systick as time base source and configure 1ms tick (default clock after Reset is HSI) */ HAL_InitTick(TICK_INT_PRIORITY); /* Init the low level hardware */ HAL_MspInit(); return HAL_OK;

　　HAL_InitTick(TICK_INT_PRIORITY) 以 SysTick 为 HAL 时基（TICK_INT_PRIORITY 在 stm32f4xx_hal_conf.h 中为 0x0F），内部调用 HAL_SYSTICK_Config(HAL_RCC_GetHCLKFreq()/1000)：此刻系统时钟还是 HSI 16MHz，所以装载值 = 16000000/1000 = 16000，即 SysTick 每 1ms 产生一次中断；中断服务函数 SysTick_Handler（stm32f4xx_it.c）中调用 HAL_IncTick() 让 uwTick 自增，供 HAL_GetTick()/HAL_Delay() 使用。

　　最后调用 HAL_MspInit()——它是 __weak 弱定义的回调，供用户重写以做底层硬件初始化（如 SYSCFG 时钟、电源管理），本工程未重写，执行空实现。

3.5 时钟初始化解析 Stm32_Clock_Init(360,25,2,8)

　　Stm32_Clock_Init 位于 SYSTEM/sys/sys.c，把系统时钟从 HSI 16MHz 切换到 PLL 倍频后的 180MHz。四个参数依次是 plln、pllm、pllp、pllq（注意参数顺序：先 N 后 M）。

3.5.1 PLL 参数与频率计算

//时钟系统配置函数 //Fvco=Fs*(plln/pllm); //SYSCLK=Fvco/pllp=Fs*(plln/(pllm*pllp)); //Fusb=Fvco/pllq=Fs*(plln/(pllm*pllq)); //外部晶振为25M的时候,推荐值:plln=360,pllm=25,pllp=2,pllq=8. //得到:Fvco=25*(360/25)=360Mhz // SYSCLK=360/2=180Mhz // Fusb=360/8=45Mhz void Stm32_Clock_Init(u32 plln,u32 pllm,u32 pllp,u32 pllq) { RCC_OscInitStructure.OscillatorType = RCC_OSCILLATORTYPE_HSE; //时钟源为HSE RCC_OscInitStructure.HSEState = RCC_HSE_ON; //打开HSE RCC_OscInitStructure.PLL.PLLState = RCC_PLL_ON; //打开PLL RCC_OscInitStructure.PLL.PLLSource = RCC_PLLSOURCE_HSE; //PLL时钟源选择HSE RCC_OscInitStructure.PLL.PLLM = pllm; //PLL之前的分频 = 25 RCC_OscInitStructure.PLL.PLLN = plln; //PLL倍频系数 = 360 RCC_OscInitStructure.PLL.PLLP = pllp; //PLL之后的分频 = 2 RCC_OscInitStructure.PLL.PLLQ = pllq; //USB/SDIO等分频 = 8 ret = HAL_RCC_OscConfig(&RCC_OscInitStructure); //初始化振荡器与PLL if(ret != HAL_OK) while(1); //失败则死循环

　　频率链路（阿波罗板外部晶振 25MHz，stm32f4xx_hal_conf.h 中 HSE_VALUE=25000000）：

环节计算结果
HSE 晶振—25 MHz
VCO 输入25M / PLLM(25)1 MHz（要求 1~2MHz）
VCO 输出1M × PLLN(360)360 MHz（要求 100~432MHz）
SYSCLK360M / PLLP(2)180 MHz（F429 最高主频）
USB/SDIO/RNG360M / PLLQ(8)45 MHz（USB 恰好需要 48M 之外的合法值域）

3.5.2 调压器与 Over-Drive

__HAL_RCC_PWR_CLK_ENABLE(); //使能PWR时钟 __HAL_PWR_VOLTAGESCALING_CONFIG(PWR_REGULATOR_VOLTAGE_SCALE1);//调压器输出电压级别1 ... ret = HAL_PWREx_EnableOverDrive(); //开启Over-Driver功能 if(ret != HAL_OK) while(1);

　　主频越高，内核对供电的要求越高。调压器级别 1（SCALE1）是支持 180MHz 的电压档位；而要让 VCO 跑到 360MHz 这类超出常规 PLL 范围的频率，必须开启 F42x/F43x 特有的 Over-Drive 模式（解除内部稳压器的频率限制）。两步缺一不可，否则 HAL_RCC_OscConfig/HAL_RCC_ClockConfig 会返回错误，代码进入 while(1) 死循环。

3.5.3 总线分频与 Flash 等待

//选中PLL作为系统时钟源并且配置HCLK,PCLK1和PCLK2 RCC_ClkInitStructure.ClockType = (RCC_CLOCKTYPE_SYSCLK|RCC_CLOCKTYPE_HCLK |RCC_CLOCKTYPE_PCLK1|RCC_CLOCKTYPE_PCLK2); RCC_ClkInitStructure.SYSCLKSource = RCC_SYSCLKSOURCE_PLLCLK; //系统时钟源=PLL RCC_ClkInitStructure.AHBCLKDivider = RCC_SYSCLK_DIV1; //AHB = 180/1 = 180Mhz RCC_ClkInitStructure.APB1CLKDivider= RCC_HCLK_DIV4; //APB1 = 180/4 = 45Mhz RCC_ClkInitStructure.APB2CLKDivider= RCC_HCLK_DIV2; //APB2 = 180/2 = 90Mhz ret = HAL_RCC_ClockConfig(&RCC_ClkInitStructure, FLASH_LATENCY_5); if(ret != HAL_OK) while(1);

　　切换 SYSCLK 到 PLL 的同时设置三级总线分频：

时钟域分频频率挂载外设示例
SYSCLK/HCLK(AHB)/1180 MHzCPU、DMA、GPIO（本实验的 GPIOB 就在此域）
PCLK1(APB1)/445 MHz低速外设；APB1 定时器自动×2 = 90MHz
PCLK2(APB2)/290 MHz高速外设；APB2 定时器自动×2 = 180MHz

　　FLASH_LATENCY_5 把 FLASH 等待周期设为 5WS（6 个 CPU 周期取一次）——180MHz 下 FLASH 取指跟不上 CPU，必须插入等待周期。另外，HAL_RCC_ClockConfig 内部在时钟切换完成后会再次调用 HAL_InitTick()，用新的 HCLK=180MHz 重建 1ms 时基（装载值变为 180000），并更新 SystemCoreClock 变量。

3.6 延时初始化解析 delay_init(180)

3.6.1 SysTick 时钟源与 fac_us

void delay_init(u8 SYSCLK) { HAL_SYSTICK_CLKSourceConfig(SYSTICK_CLKSOURCE_HCLK);//SysTick频率为HCLK fac_us = SYSCLK; //fac_us = 180，即每 1us 需要 180 个节拍 //本工程 sys.h 中 SYSTEM_SUPPORT_OS=0，不使用 ucos，其余分支不编译 }

　　两件事：① 把 SysTick 的时钟源设为 HCLK（180MHz），而不是 HCLK/8（45MHz），由 SysTick->CTRL 的 CLKSOURCE 位控制；② 记录延时倍乘数 fac_us = 180——因为 SysTick 是纯计数器（不涉及任何分频寄存器换算），延时 nus 需要 nus × 180 个计数节拍。此时 SysTick 仍在以 HAL_Init/ClockConfig 建立的 1ms 周期产生中断，delay 函数只是"搭便车"读取它的递减计数器。

3.6.2 delay_us 与 delay_ms 原理

void delay_us(u32 nus) { u32 ticks; u32 told,tnow,tcnt=0; u32 reload = SysTick->LOAD; //LOAD 的值（1ms 对应 180000-1） ticks = nus * fac_us; //需要的节拍数 = nus*180 told = SysTick->VAL; //刚进入时的计数器值 while(1) { tnow = SysTick->VAL; if(tnow != told) { if(tnow<told) tcnt += told-tnow; //正常递减，累计差值 else tcnt += reload-tnow+told; //发生过一次重装载（计数器回绕） told = tnow; if(tcnt >= ticks) break; //累计节拍数达到目标，退出 } }; } void delay_ms(u16 nms) { u32 i; for(i=0;i<nms;i++) delay_us(1000); //逐次 1ms 拼接，避免 24 位计数器溢出 }

　　SysTick 是一个递减计数器：从 LOAD 递减到 0 后重装载 LOAD 再继续。delay_us 不等待中断，而是轮询 SysTick->VAL，把每次观测到的差值累加（含回绕补偿），累计节拍数达到 nus×fac_us 即结束——与 OS 版本的差别仅在不需要锁定调度。delay_ms 用"每次 1ms 循环 nms 次"的方式突破 SysTick 24 位计数器单次最大约 0.093s@180MHz 的限制，主循环中的 delay_ms(500) 即由此而来。

3.7 LED 初始化解析 LED_Init()

3.7.1 led.h 引脚宏与位带操作

//led.h #define LED0 PBout(1) //LED0 —— PB1 的位带别名 #define LED1 PBout(0) //LED1 —— PB0 的位带别名 //sys.h 中的位带实现（Cortex-M4 外设位带区）： #define BITBAND(addr, bitnum) ((addr & 0xF0000000)+0x2000000+((addr &0xFFFFF)<<5)+(bitnum<<2)) #define MEM_ADDR(addr) *((volatile unsigned long *)(addr)) #define BIT_ADDR(addr, bitnum) MEM_ADDR(BITBAND(addr, bitnum)) #define GPIOB_ODR_Addr (GPIOB_BASE+20) //0x40020414 #define PBout(n) BIT_ADDR(GPIOB_ODR_Addr,n) //输出

　　位带（Bit-Band）把 ODR 寄存器的一个位膨胀为别名区的一个 32 位字，实现"写一个地址 = 改一个位"，效果类似 51 单片机的 sbit。以 LED0（PB1）为例：GPIOB_ODR 地址 0x40020414，代入公式得别名地址 0x42000000 + (0x20414<<5) + (1<<2) = 0x42408284，于是 LED0 = 0 就是向该地址写 0，等价于把 PB1 的输出锁存位清零（灯亮）。

手册第十三章（新修订驱动）采用了另一种封装风格：LED0_GPIO_PORT/PIN/CLK_ENABLE 三组宏 + LED0(x) 条件宏。本工程为经典写法（LED_Init + PBout 位带宏），两者功能等价，本页以工程实际代码为准解析。

3.7.2 GPIO_InitTypeDef 与 LED_Init

void LED_Init(void) { GPIO_InitTypeDef GPIO_Initure; __HAL_RCC_GPIOB_CLK_ENABLE(); //开启GPIOB时钟 GPIO_Initure.Pin = GPIO_PIN_0|GPIO_PIN_1; //PB1,0 GPIO_Initure.Mode = GPIO_MODE_OUTPUT_PP; //推挽输出 GPIO_Initure.Pull = GPIO_PULLUP; //上拉 GPIO_Initure.Speed = GPIO_SPEED_HIGH; //高速 HAL_GPIO_Init(GPIOB,&GPIO_Initure); HAL_GPIO_WritePin(GPIOB,GPIO_PIN_0,GPIO_PIN_SET); //PB0置1，默认初始化后灯灭 HAL_GPIO_WritePin(GPIOB,GPIO_PIN_1,GPIO_PIN_SET); //PB1置1，默认初始化后灯灭 }

　　LED_Init 正是 1.4 节"GPIO 输出配置三步骤"的具体落地：① __HAL_RCC_GPIOB_CLK_ENABLE() 把 RCC->AHB1ENR 的 GPIOBEN 置 1（宏内部含"写后读"延时以稳定时钟）；② 填充 GPIO_InitTypeDef（成员取值见 1.4 节表格：PB0/PB1、推挽输出、上拉、高速），调用 HAL_GPIO_Init 写入 GPIOB 四个配置寄存器（写入值见 1.4 节落地表）；③ HAL_GPIO_WritePin 把 PB0/PB1 预置为高——LED 阴极接 IO，高电平即初始"灯灭"状态，避免上电瞬间灯乱闪。

　　对照原理图：PB0/PB1 复位后默认是模拟模式（GPIOB->MODER 复位值 0xFFFFFEBF），HAL_GPIO_Init 把它们切换成"推挽输出"，驱动 LED 毫无压力。

3.8 主循环解析 while(1) 跑马灯

3.8.1 while(1) 交替闪烁

while(1) { HAL_GPIO_WritePin(GPIOB,GPIO_PIN_1,GPIO_PIN_RESET); //LED0对应引脚PB1拉低，亮 HAL_GPIO_WritePin(GPIOB,GPIO_PIN_0,GPIO_PIN_SET); //LED1对应引脚PB0拉高，灭 delay_ms(500); //延时500ms HAL_GPIO_WritePin(GPIOB,GPIO_PIN_1,GPIO_PIN_SET); //LED0对应引脚PB1拉高，灭 HAL_GPIO_WritePin(GPIOB,GPIO_PIN_0,GPIO_PIN_RESET); //LED1对应引脚PB0拉低，亮 delay_ms(500); //延时500ms }

　　逻辑与手册 13.3.2 节程序流程图完全一致：LED0 亮 + LED1 灭 → 延时 500ms → LED0 灭 + LED1 亮 → 再延时 500ms → 无限重复，两灯以 1s 为周期交替点亮，肉眼观感即为"跑马灯"。

3.8.2 HAL_GPIO_WritePin 与 BSRR

void HAL_GPIO_WritePin(GPIO_TypeDef *GPIOx, u16 GPIO_Pin, GPIO_PinState PinState) { if(PinState != GPIO_PIN_RESET) GPIOx->BSRR = GPIO_Pin; //SET：低16位写1 → 输出高电平（灯灭） else GPIOx->BSRR = (uint32_t)GPIO_Pin << 16; //RESET：高16位写1 → 输出低电平（灯亮） }

　　WritePin 只有一条写 BSRR 的语句：SET 走低 16 位（置位区）、RESET 走高 16 位（复位区）。BSRR 写 0 的位不产生任何影响，因此一次 32 位写入只改变目标引脚，且原子生效、不可被中断打断——这正是 1.3 节所述 BSRR 优于 ODR 的地方，也是多任务/中断环境下推荐的控制方式。

3.8.3 三种输出方式对比

　　main.c 中保留了同一跑马灯的三种写法（另两种以注释形式存在），控制效果完全相同：

方式示例代码特点
HAL 库HAL_GPIO_WritePin(GPIOB, GPIO_PIN_1, GPIO_PIN_RESET);可读性/可移植性最好，屏蔽了寄存器细节
位带操作LED0 = 0;（即 PBout(1) = 0）写位带别名地址 0x42408284，像 51 的 sbit 一样简洁
直接寄存器GPIOB->BSRR = GPIO_PIN_1; / GPIOB->BSRR = GPIO_PIN_0 << 16;效率最高、最贴近硬件，适合对时序敏感的场景

　　三种方式最终都殊途同归：写 GPIOB 的 BSRR 寄存器改变 PB0/PB1 电平。HAL 库是封装、位带是映射、寄存器是本体，理解了 BSRR 就理解了全部。

本章小结（软件设计全链路）

① 上电复位：硬件从向量表装载 MSP（栈顶 1KB）与 PC，进入启动文件的 Reset_Handler；② SystemInit：开 FPU、复位时钟寄存器、VTOR 指向 0x08000000（此时仍是 HSI 16MHz）；③ __main：C 库完成 RW 搬运、ZI 清零、堆栈初始化，进入用户 main；④ HAL_Init：开 Flash 缓存/预取、NVIC 分组 2、以 HSI 16MHz 建立 1ms SysTick 时基；⑤ Stm32_Clock_Init(360,25,2,8)：HSE 25MHz 经 PLL 倍频为 180MHz 主频，FLASH 5WS；⑥ delay_init(180)：SysTick 时钟源取 HCLK，fac_us=180；⑦ LED_Init：使能 GPIOB 时钟，配置 PB0/PB1 推挽输出并预置高电平；⑧ 主循环：HAL_GPIO_WritePin 经 BSRR 让两灯每 500ms 交替亮灭。
